## 1. 项目定位

做一个 PCB 表面缺陷的**二次复检系统**，挂在现有检测器之后。检测器负责快速定位，正常模板提供"该位置本来应该是什么"的参照，图像处理模块把细微差异转成可看清的证据，多模态大模型对高风险候选做一次独立判断，两级决策规则控制"要不要看"和"敢不敢改"。

对应到产线语义：这是 AOI 之后的自动复判环节，目标是在不显著增加单板检测时间的前提下降低误报，同时不把原本判对的缺陷改错。

**方案沿革**：早期开题稿的方法设计有五处已被否定（配准未建模、风险分数手工加权、大模型被检测结果锚定、依赖大模型自报置信度、差异候选粒度过粗），`PCB_MLLM_EviGate_Research_Design.md` 给出了修正后的方案，实现一律以它为准。开题稿中仍有价值的论文章节结构与题目备选已并入本文 §10，原文件不再保留。

## 2. 系统总体方案

```
待检图 I ──┬─→ [M1 配准与归一] ──→ 配准质量 q_reg
正常模板 R ─┘         │
                      ├─→ [M2 外观差异] ─┐
                      └─→ [M3 结构差异] ─┴─→ [M4 差异候选 C_diff] ─┐
                                                                    │
I ──→ [M0 基础检测器 + 置信度校准] ──→ 检测候选 C_det ──────────────┤
                                                                    ↓
                                                      [M5 候选融合，标记来源]
                                                                    ↓
                                            [M6 复检门] ──低风险──→ 默认动作
                                                    ↓ 高风险
                                        [M7 证据卡] → [M8 大模型独立判断]
                                                    ↓
                                        [M9 动作映射] → [M10 接受门 + 安全规则]
                                                    ↓
                                        [M11 类别感知 NMS] → 最终结果 + 审计日志
```

候选来源标记三种：`DET`（仅检测器）、`DIFF`（仅差异模块）、`BOTH`（两者共同支持）。
候选动作六种：`keep` / `remove` / `relabel` / `add` / `reject` / `defer`。

模块职责一句话：

| 模块 | 输入 | 输出 | 是否创新点 |
|---|---|---|---|
| M0 基础检测器 | 待检图 | 框+类别+校准置信度 | 否，工具 |
| M1 配准与光度归一 | 待检图、模板 | 对齐模板、`q_reg` | 支撑 |
| M2 外观差异 | 对齐后两图 | `M_app` 热图 | **已推翻**：作为大模型视觉输入无效，仅用于生成差异候选 |
| M3 结构差异 | 对齐后两图 | `M_topo` + 8 维拓扑向量 | **重新定位**：拓扑向量作为门控特征，差异图不进证据卡 |
| M4 差异候选生成 | 差异图 | `C_diff` | 创新点 1 |
| M5 候选融合 | `C_det`、`C_diff` | 统一候选 + 来源标记 | 创新点 1 |
| M6 复检门 | 候选特征 | 风险分数，决定是否调用大模型 | 创新点 3 |
| M7 证据卡 | 候选 + 各类图 | 2×3 面板图 | 创新点 2 |
| M8 大模型复检 | 证据卡 + 缺陷定义 | 固定 JSON 判断 | 支撑 |
| M9 动作映射 | 大模型输出 + 来源 | 提议动作 | 创新点 3 |
| M10 接受门 | 证据特征 + 提议动作 | 是否执行 | 创新点 3 |
| M11 最终融合 | 全部动作 | 最终框 + 审计记录 | 支撑 |

**创新点与实验结论的对应（2026-08-12 修订）**

| 原创新点 | 对应模块 | 实验结论 |
|---|---|---|
| 双来源候选 | M4 + M5 | **保留**。漏检恢复率 0.625，候选上界 0.9555 留有 +0.044 空间 |
| 外观—拓扑证据表示 | M2 + M3 + M7 | **已推翻**。全部变体低于仅用模板的 A2，改为负面消融结论 |
| 去锚定 + 双门控 | M6 + M9 + M10 | **拆开**。双门控保留并强化（TPRR 0.9998）；去锚定被 label_aware 对照动摇 |

证据卡最终定义为 **A2**：当前紧裁剪（P1）、正常模板紧裁剪（P2）、更大上下文（P3），
不含外观差异图与拓扑差异图。8 维拓扑向量作为门控特征保留。

## 3. 已确定的设计决策

### 3.1 运行环境与算力

- 代码、数据、实验全部放在 **T4 服务器** `<repo-root>`（内网服务器），本地只保留文档。
- GPU：4 × Tesla T4，每张 15GB。磁盘 `<data-disk>` 余量约 197G。
- Python 环境：`<conda-env>`，Python 3.11 + cv2 5.0.0 + numpy 2.4.6 + skimage 0.26.0。
  解释器绝对路径 `python`。与服务器原有的 anaconda3 相互独立。
- 网络：国内源（清华 pypi/conda）走直连，**不要挂代理**，挂代理会绕道境外反而慢十几倍；
  只有 codex 和 GitHub 需要 `https_proxy=http://127.0.0.1:7897`。
- 检测器在 T4 上训练，模型规模控制在 YOLOv8s 或同级，交叉拟合 3 折加一个全量模型共 4 次训练。
- 大模型走 **API**，不做本地部署，不做 LoRA 微调。
- 主模型选一个国内可稳定调用的视觉大模型（Qwen-VL 系列优先），跨模型验证只在 20% 子集上做一次。

### 3.2 开发分工

- Claude 作为 main agent 负责监督、调度、进度管理和验收，不编写业务代码。
- 代码编写与 code review 交给 `codex exec`，模型 `gpt-5.6-sol`，推理档位 `medium`
  （2026-08-11 起；阶段 0 到阶段 3 用的是 gpt-5.6-luna）。
- 每个阶段由 main agent 拆任务、写清接口约定与验收标准，codex 实现，main agent 检查产出后决定是否进入下一阶段。

### 3.3 调用预算（拍板：诊断集 800 + 基线减配）

- **RQ1 证据消融**：在 800 个分层采样的候选诊断集上跑全部消融配置。
- **B3–B7 基线**：只在同一诊断集上跑，不在全测试集全量调用。
- **端到端全量**：只跑 B0、B1、B7、Full 四条。
- 预计总调用量 2–3 万次。开工前先跑 100 个候选的预实验，测出真实单位成本和 JSON 解析率，再确认预算。

### 3.4 缓存

缓存 key 用可读字符串拼接：`{候选ID}__{证据配置名}__{模型名}__t{温度}`，例如 `img042_c07__A6__qwen-vl-max__t0`。命中直接复用，跨实验共享。所有大模型响应落盘为 JSONL，实验可离线重跑。

不做内容哈希、不做校验和。这是全项目的通用约束：**拒绝防御性编程**，不引入 SHA256 校验、冗余断言、层层兜底这类拖慢开发节奏的机制。给 codex 下任务时要带上这条。

### 3.5 新增框的分数赋值（拍板）

- `add` 产生的框：score = 接受门输出的 `accept_prob`。
- `relabel` 的框：保留检测器原始校准置信度。
- `keep`：不变。
- 论文中需明确写出这条规则，并在附录补一组"add 固定 0.5"的对照，说明 mAP 对该选择不敏感（或说明敏感程度）。

### 3.6 BOTH 候选的框一致性（拍板）

- 大模型看**融合框**范围的上下文，但 `keep`/`relabel`/`remove` 三个动作一律作用于**检测器原框**。
- `BOTH` 候选不允许 `add`（位置已被检测框覆盖）。
- 若检测框与差异框 IoU < 0.1（即仅靠中心点规则被合并），拆回两个独立候选各自走流程。

### 3.7 划分与防泄漏（拍板，2026-08-11 定）

**主方案：按模板组做 GroupKFold 5 折。** 依据是官方划分已被证实有模板泄漏（11 组中 7 组跨 train/test，见 §4.1），
且 11 个组规模差 23 倍、最大组独占 21.7%，单次划分的运气成分太大。5 折能把折间方差显式报出来。

每折的角色分配：

| 角色 | 组成 | 用途 |
|---|---|---|
| test | 第 i 折 | 端到端评价；同时产出该折图像的 out-of-fold 预测 |
| val | 第 (i+1)%5 折 | 温度缩放、阈值选择、prompt 定稿 |
| train | 其余 3 折 | 训练检测器 |

**交叉拟合并入折结构，不再单独做 K=3。** 5 折本身就给出全部 1500 张图的 OOF 预测：
每张图恰好在一折里当过 test，那一折的检测器没见过它。这些预测直接作为门控训练数据。
检测器训练次数因此是 **5 次**，不是原方案的 4 次加内层折叠共 20 次。

门控训练同样按折隔离：评价第 i 折时，门控只用其他 4 折的 OOF 预测训练。

其他约定：

- **单随机种子**。置信区间靠按图像聚类的 bootstrap，加上折间标准差，不靠多种子重复。
- 折的分配由 `sklearn.model_selection.GroupKFold` 按组大小贪心平衡，实际每折图像数需在数据管线里打印并记入 §4.2。
- 官方划分只跑一次作为与已有论文的对比参考，不作为主结论。

### 3.8 大模型接口约定（2026-08-12 实验后修订）

**主后端定为本机 codex CLI**，不用外部 API key。实测可行：

```
https_proxy=http://127.0.0.1:7897 codex exec \
  -m gpt-5.6-sol -c model_reasoning_effort=low \
  -i <证据卡.png> --output-schema <schema.json> -o <输出.json> \
  --skip-git-repo-check "<prompt>"
```

`--output-schema` 强制输出符合 JSON Schema 的结果，`-o` 把最终消息写入文件，直接读文件解析，
不要解析 stdout 日志。实测单次约 29 秒，因此必须多进程并发（默认 4 路）且强依赖缓存。

三个后端并存，由 `configs/mllm/*.yaml` 切换：

| 后端 | 用途 | 状态 |
|---|---|---|
| `codex_cli` | 主后端，真实多模态判断，模型 `gpt-5.6-sol` | 已实测可用 |
| `stub` | 快速迭代与 CI，确定性规则生成合法 JSON，不看 GT | 供开发用 |
| `openai_compatible` | 将来接 DashScope Qwen-VL 等 | 写好待用，当前无 key |

**实测吞吐上限约 26 次每分钟**（12 路并发，瓶颈在 API 侧而非本地）。
累计完成约 7000 次真实调用，全部缓存可复现。这个吞吐数字是方法的工程约束，
论文的计算开销章节应如实报告：全量 RQ1（800 候选 × 12 组 = 9600 次）需约 6 小时。

其他约定：

- 不向大模型提供检测器类别与置信度（去锚定），保留 `label_aware` 开关供 RQ1 对照。

**动作优先级调整（2026-08-11 决策，有五折数据支撑）**

五折收敛检测器的错误分解显示三类可纠错错误的数量极不均衡：

| 动作 | 对应错误 | 五折数量 | 占比 |
|---|---|---:|---:|
| `add` | 漏检 | 947 | 57.6% |
| `remove` | 误报 | 636 | 38.7% |
| `relabel` | 错分类 | 61 | 3.7% |

因此 prompt 设计从"三类动作等价"调整为**优先 add 与 remove**：

1. 不再要求模型主动给出类别用于改类。仅当模型给出的类别与拓扑证据严重矛盾时才允许提 `relabel`，
   其余情况下类别不同不触发 relabel，退化为 `keep`。
2. 强化 `normal` 判断的引导。`remove` 依赖模型敢于判定"此处无缺陷"，
   而 smoke 显示 stub 与真实模型都倾向于永远返回 `defect_present=true`。
   prompt 中需明确给出"何种证据组合应判为 normal"的描述。
3. DIFF 来源候选的提示词强调"这是检测器未提出的区域，请独立判断是否存在缺陷"，
   服务于 `add` 路径。

**这一调整依据的是 train 折的错误统计，不是 test 折**，符合参数只在训练与验证集上确定的要求，
论文中需说明该设计选择的依据来源。

**实验后的验证结果（2026-08-12）**

| 对照 | 存在性 F1 | normal 判定率 | 结论 |
|---|---:|---:|---|
| prompt_v1 | 0.7678 | 0.31 | F1 更高 |
| prompt_v2（含动作优先级调整） | 0.7347 | 0.39 | normal 判定更好 |

两个目标在打架：**v2 的存在性 F1 更低，但 normal 判定率更高**，
而 `remove` 路径依赖模型敢判 normal（对应 636 个误报）。
论文中应把这个权衡讲清楚，不能只报 F1。smoke 阶段 prompt_v1 的 normal 判定率为 0.000，
v2 把它提到 0.39 以上，`remove` 路径因此才可用。

**证据卡最终定义为 A2**（P1 当前紧裁剪、P2 正常模板紧裁剪、P3 更大上下文）。
外观差异图与拓扑差异图**不进证据卡**，依据是阶段 B2 的 450 次专门对照：
A2 0.8082 高于 A6F 0.7778、A6 0.7763、A2T 0.7481、A2N 0.7183，
且已排除渲染自动拉伸与配准残差两个混淆因素。

**去锚定设计被动摇（已推翻，待论文如实报告）**：
A6_label_aware 0.7701 高于去锚定的 A6 0.7347。置信区间有重叠不能称显著，但方向明确。

**配准不可靠提示是负资产**：A6_no_reg_warning 0.8000 为全场最高，
该提示让模型过度保守。
- 输出固定 JSON，字段与枚举见方法方案 §23，直接照抄。
- 解码温度 0，解析失败重试一次，仍失败则默认不修改。
- prompt 定稿后打版本号冻结（如 `prompt_v1`），测试集上不再改。

### 4.1 DeepPCB 实际结构（2026-08-11 实测）

目录组织 `PCBData/group{模板ID}/{模板ID}/` 存图，`PCBData/group{模板ID}/{模板ID}_not/` 存标注。
每对图为 `{编号}_test.jpg` 与 `{编号}_temp.jpg`，标注为同名 `.txt`。

- 图像：3001 张，全部 640×640 JPEG；2939 张单通道灰度，**62 张为 RGB**（需按灰度统一读取）
- 图像对：1500 对；官方划分 `trainval.txt` 1000 行、`test.txt` 500 行
- 标注格式：每行 `x1 y1 x2 y2 类别id`，空格分隔
- 模板组：**11 个**，各组图像对数极不均衡

| 组 | 对数 | 组 | 对数 | 组 | 对数 |
|---|---:|---|---:|---|---:|
| group20085 | 325 | group92000 | 120 | group50600 | 79 |
| group00041 | 221 | group77000 | 107 | group90100 | 74 |
| group13000 | 216 | group44000 | 100 | group12000 | 14 |
| group12100 | 146 | group12300 | 98 | | |

最大组是最小组的 23.21 倍。这个不均衡直接影响 §3.7 的分组划分方案，见 §9 第 4 条。

| 组 | 总对数 | trainval | test | 组 | 总对数 | trainval | test |
|---|---:|---:|---:|---|---:|---:|---:|

其中 group12000/12100/12300/90100 共 332 对完全不在 trainval，是官方留出的未见模板；
其余 7 组则在两侧都有样本，存在模板泄漏。用官方划分报的数会偏高，这一点在论文里要写明。

**类别映射**（实测标注文件，非 README 文字）：1 open，2 short，3 mousebite，4 spur，5 copper（即 spurious copper），6 pin-hole。0 为 background 未使用。

**缺陷规模**：10013 个框。每图缺陷数中位数 7（最小 1，最大 15）。
框宽中位数 35，框高中位数 33，面积中位数 1184 px²。最小框 20×20（面积 400）。
按此，证据卡紧裁剪 1.5–2 倍后约 50–70 px，需上采样到 256×256 才能让大模型看清，
§3 的证据卡参数据此确定。

### 4.2 划分

DeepPCB 主结论用按模板组的 GroupKFold 5 折，方案见 §3.7。官方划分只作为与已有论文的对比参考。

|---|---|---|---|
| fold_0 | group20085 | group00041、group50600 | group12000、group12100、group12300、group13000、group44000、group77000、group90100、group92000 |
| fold_1 | group00041、group50600 | group12300、group13000 | group12000、group12100、group20085、group44000、group77000、group90100、group92000 |
| fold_2 | group12300、group13000 | group12000、group12100、group44000 | group00041、group20085、group50600、group77000、group90100、group92000 |

### 5.5 RQ4 鲁棒性（简化版）

- 人工配准扰动：平移 ±1/±2/±4/±8 px，旋转 ±0.5°/±1°/±2°。对比"直接骨架异或"与"容差异或"，对比有无配准质量门。
- 光照扰动：亮度 ±20%，高斯噪声 σ=5/255，模糊 σ=1.0。
- 模型替换：检测器换 RT-DETR-R18，大模型换第二个，均在 20% 子集上做。
- HRIPCB 跨模板测试。

**不做**：conformal 风险控制、多重比较校正、AURC/ECE 这类校准指标的完整报告。校准只画一张接受门的可靠性曲线作定性说明。统计上只做按图像聚类的 bootstrap 置信区间，够学位论文用。

## 6. 评价指标

**常规检测**：Precision、Recall、F1、mAP@0.5、mAP@0.5:0.95、每类 AP。

**纠错行为**（这组是论文的重点，比 mAP 更能说明系统价值）：

| 指标 | 定义 |
|---|---|
| 误报修正率 FPCR | 正确删除的原始误报 / 原始误报总数 |
| 漏检恢复率 MDRR | 复检后新增匹配的原始漏检 / 原始漏检总数 |
| 类别修正准确率 MCCA | 正确重分类数 / 原始错分类数 |
| 正确检测保留率 TPRR | 复检后仍正确的原始 TP / 原始 TP 总数 |
| 有害修正率 HCR | 降低检测效用的已接受修改 / 全部已接受修改 |
| 动作精度 | 带来正效用的已接受修改 / 全部已接受修改 |

TPRR 是硬约束，优先保证；具体阈值在验证集上定，不能事后挑。

**成本**：大模型调用率、每图调用次数、平均与 P95 时延、每图 token 数、配准失败回退率。

状态标记：已确认 / 已解决 / 已推翻。

1. **DeepPCB 是否已预配准**（**已确认：未预配准**）。50 对随机样本实测：

2. **DeepPCB 是否为二值图**（**已确认：近二值，非严格二值**）。3001 张图中严格二值（唯一值≤2）只有 3 张（0.10%），

### 10.2 三点贡献（按实验结果改写）

原方案的三个创新点经实验检验后调整为：

**贡献一：面向漏检恢复的双来源候选机制**

联合检测器语义候选与正常模板差异候选，在统一候选空间中处理误报、错分类与检测器
未提出候选的漏检。实验支撑：差异候选的漏检恢复候选率 0.625（IoU 0.3），
候选上界 F1 0.9555 相对基线 0.9118 留有 +0.044 空间，证明候选覆盖不是瓶颈。
五折错误分解显示漏检占可纠错空间 57.6%，是最大错误类型，该机制针对的正是主要矛盾。

**贡献二：风险受控的分级复检机制**

学习式复检门控制调用预算，外部证据驱动的接受门约束修改动作。实验支撑：

- 复检门在 5% 调用预算下定位 46.5% 的可纠错错误，随机策略仅 3.2%，效率 14.8 倍
- 接受门保证任何调用预算下最终 F1 不低于基线；无接受门时 F1 随预算从 0.9088 跌至 0.8660
- 正确检测保留率 0.9998，734 个正确检测仅误删 2 个
- 无门控时有害修正率 0.9326，双门控将其阻断

这是全文最强的实证结论。

**贡献三：多模态大模型作为工业细粒度缺陷验证器的能力边界实证**

把原创新点二的失败转为正面贡献。实验支撑：

- 证据消融证明**正常模板是唯一稳定的增益来源**（A2 相对 A0 +0.1178，CI 不跨 0），
  而外观差异图、拓扑差异图、数值拓扑摘要的全部变体均低于仅用模板的配置
- 已排除渲染自动拉伸与配准残差两个混淆解释
- Oracle 分析将瓶颈精确定位：候选上界 0.9555 留有空间，但**接受上界仅 0.9143，
  比基线高 0.0025**，说明大模型提出的修改中缺乏足够多的正确项
- 附加对照进一步刻画边界：去锚定未见收益、配准不可靠提示为负资产、
  自由文本输出的 JSON 可解析率为 0
